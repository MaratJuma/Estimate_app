# PROJECT_NOTES.md

## 1. Назначение проекта

Проект представляет собой Django-систему для управления сметами, поставщиками и услугами.

Основные задачи системы:
- ведение справочника поставщиков
- ведение справочника услуг
- создание и редактирование смет
- разбивка сметы по дням
- добавление позиций в смету
- расчёт себестоимости, клиентской стоимости и маржи
- утверждение смет
- печать смет
- экспорт рабочей сметы в Excel
- разграничение доступа по ролям пользователей

6. Бизнес-логика расчётов

По позиции сметы

total_cost = qty * cost_price
total_client = qty * client_price

Маржа

margin = total_client - total_cost

Маржа в процентах

margin_percent = margin / total_client
если total_client == 0, то margin_percent = 0

По дню

Суммируются:


себестоимость всех позиций
сумма клиенту всех позиций
маржа

По всей смете

Суммируются итоги всех дней.

Текущая логика

admin и production_manager имеют доступ к редактированию услуг
sales_manager имеет доступ только к просмотру карточки услуги без редактирования
редактирование смет возможно только при соответствующих правах
утверждённые сметы недоступны для изменения

8.4. Добавление позиции в смету

Текущая логика:


1.
пользователь открывает каталог услуг для конкретного дня сметы
2.
использует:
поиск по названию
фильтр по категории
фильтр по поставщику
3.
выбирает услугу в таблице
4.
попадает на форму добавления выбранной услуги в смету
5.
указывает количество
6.
после сохранения возвращается в смету

8.5. Редактирование позиции сметы

Редактирование позиции — отдельный сценарий:


услуга уже выбрана
редактируются только:
количество
цена клиенту
сама услуга не пере выбирается

12. Git workflow

Основное правило:
код изменяется локально, затем отправляется в Git, затем подтягивается на VPS.


Локально

git status
git add .
git commit -m "Описание изменений"
git push origin main

На VPS

cd ~/Estimate_app
git pull
source venv/bin/activate
python manage.py check
sudo systemctl restart gunicorn
sudo systemctl restart nginx

Если изменялись зависимости

pip install -r requirements.txt

Если изменялись модели

python manage.py migrate

Если изменялась статика

python manage.py collectstatic --noinput

17. Рекомендации по безопасности

Обязательно

DEBUG=False в production
использовать .env для секретов
не хранить секреты в Git
проверять права доступа во view, а не только в шаблонах
регулярно делать backup PostgreSQL
обновлять пароль БД и SECRET_KEY, если они были где-либо засвечены

Желательно

настроить SSH по ключам
проверить UFW / firewall
ограничить доступ к PostgreSQL извне
позже добавить аудит действий пользователей
